# 식당 리스트 - 홈 화면 아이콘 수정 + 코드 정리

## 아이콘이 "식"만 떴던 이유

캐시 문제가 아니라 **아이콘 태그를 넣은 위치** 문제였습니다. 두 가지가 겹쳐 있었습니다.

1. **Vercel의 `index.html`이 0.8초 뒤 Apps Script로 `location.replace()`** 했습니다.
   Safari에서 "홈 화면에 추가"를 누르는 시점의 최상위 문서는 이미 `script.google.com`
   입니다. iOS는 그 시점의 최상위 문서에서만 아이콘을 읽으므로, Vercel 페이지의
   `apple-touch-icon`은 읽히기 전에 사라졌습니다.

2. **Apps Script HTML의 `<head>`는 iframe 안**에 있습니다. HtmlService는 사용자 HTML을
   구글 외곽 페이지의 샌드박스 iframe(`userCodeAppPanel`)에 넣어 서빙합니다. Safari는
   최상위 문서만 보고, 구글 외곽 페이지에는 `apple-touch-icon`이 없습니다. 그래서 iOS가
   **제목 첫 글자로 문자 아이콘을 자동 생성** → `setTitle('식당 리스트')`의 `식`.

즉 Safari 데이터 삭제나 카카오 디버거로는 고쳐질 수 없는 문제였습니다.

## 먼저 결정할 것: 배포 액세스 권한

현재 배포 URL은 **구글 로그인을 요구**합니다 (`accounts.google.com`으로 리다이렉트됨).
그리고 `accounts.google.com`은 `X-Frame-Options: DENY`를 보내므로 **로그인 페이지는
iframe 안에서 절대 렌더링되지 않습니다.**

### 옵션 A (권장) — 액세스를 "모든 사용자"로 변경, iframe 방식

Apps Script → 배포 관리 → 편집 → **액세스 권한: 모든 사용자**

- `index.html` 사용 (이미 준비됨)
- 아이콘, 앱 이름, standalone 실행 모두 정상. 주소창 없이 진짜 앱처럼 동작
- 데이터는 새 `code.gs`의 **서버 측 토큰 인증**이 보호합니다. URL이 공개되어도
  아이디/비밀번호 없이는 시트에 접근할 수 없습니다

### 옵션 B — 구글 로그인 유지, 버튼 방식

- `index-option-b.html`을 `index.html`로 **이름 변경**해서 사용
- 자동 리다이렉트를 하지 않으므로 Safari에서 페이지에 머물러 아이콘이 정상 등록됨
- 홈 화면 아이콘으로 실행하면 자동으로 앱으로 이동
- 단점: 앱이 별도 브라우저 뷰(상단 바 있음)로 열림

## 파일

| 파일 | 올릴 곳 |
|---|---|
| `index.html` | GitHub 저장소 **루트** (옵션 A) |
| `index-option-b.html` | 옵션 B 선택 시 `index.html`로 이름 변경해서 루트에 |
| `manifest.json` | GitHub 저장소 루트 |
| `apple-touch-icon.png` (180×180) | GitHub 저장소 루트 |
| `icon-192.png` (192×192) | GitHub 저장소 루트 |
| `icon-512.png` (512×512) | GitHub 저장소 루트 |
| `apps-script/code.gs` | Apps Script의 `code.gs` |
| `apps-script/index.html` | Apps Script의 **`Index`** html 파일 |

아이콘 PNG는 `IMG_9246.jpeg`에서 변환했습니다. 원본에 둥근 모서리와 회색 여백이 구워져
있어서 iOS 마스크와 이중으로 깎이는 문제가 있었으므로, 여백을 잘라내고 모서리를 메워
완전한 정사각형(알파 없음)으로 만들었습니다.

## 적용 순서

1. `apps-script/code.gs`, `apps-script/index.html` 내용을 Apps Script에 붙여넣기
2. Apps Script 편집기에서 `setupCredentials` 함수를 **한 번 직접 실행**
   (계정을 스크립트 속성으로 옮김. 안 해도 기본값으로 동작함)
3. 옵션 A라면 배포 액세스 권한을 "모든 사용자"로 변경
4. **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** (URL 유지됨)
5. PNG 3개 + `index.html` + `manifest.json`을 GitHub 루트에 커밋 → Vercel 자동 배포
6. 아이폰에서 **기존 홈 화면 아이콘을 길게 눌러 삭제**
   (iOS는 아이콘을 URL 단위로 캐싱하고 Safari 데이터 삭제로도 지워지지 않습니다)
7. Safari에서 Vercel 주소를 새로 열고 "홈 화면에 추가"

**확인 방법:** 옵션 A는 주소창이 `script.google.com`으로 바뀌지 않고 Vercel 도메인에
머물러 있어야 정상입니다.

## 코드에서 고친 것

### 동작이 틀렸던 부분

- **이용 내역의 +/− 부호와 색이 반대**였습니다. 서버로는 `'사용'`을 보내는데 렌더링에서는
  `item.type === "차감"`으로 비교해 절대 일치하지 않았고, 차감 기록이 전부 초록색 `+`로
  표시됐습니다. 이제 `'추가'`가 아닌 값은 모두 차감으로 처리합니다
- **차감 버튼 라벨이 `차감` → `이용 기록`으로 바뀌어** 돌아오지 않았습니다
- **동시 처리 시 잔액이 유실**됐습니다. 두 명이 같이 누르면 나중 값이 앞의 변경을
  덮어썼습니다. `LockService`로 직렬화했습니다
- **로그 시트가 없으면 잔액만 바뀌고 기록이 사라졌습니다.** 시트 존재 확인을 잔액 수정
  *전*으로 옮겼습니다
- **잔액 칸이 비어 있으면 화면이 멈췄습니다** (`undefined.toLocaleString()`)
- **금액 검증이 없어** `0`, 음수, 소수가 그대로 시트에 들어갔습니다. 이제 클라이언트와
  서버 양쪽에서 1 이상의 정수만 통과합니다
- **잔액이 음수로 내려갔습니다.** `ALLOW_NEGATIVE_BALANCE = false`로 막았습니다.
  초과 사용을 허용해야 하면 `code.gs`에서 `true`로 바꾸세요
- **시트 값의 앞뒤 공백** 때문에 식당을 못 찾는 경우가 있었습니다. 비교 시 항상 정리합니다
- **선택 상태를 버튼 글자로 비교**해서 같은 이름의 식당이 있으면 여러 개가 동시에 선택된
  것처럼 보였습니다. `data-value` 기준으로 바꿨습니다
- **시트 내용이 그대로 `innerHTML`에 들어가** 이름에 `<`나 `&`가 있으면 레이아웃이
  깨졌습니다. 이스케이프 처리했습니다
- **내역이 50건에서 조용히 잘렸습니다.** 이제 "전체 N건" 표시가 나옵니다

### 보안

가장 큰 문제는 **아이디/비밀번호가 클라이언트 JS에 평문으로** 있던 것입니다.
브라우저 소스 보기만 하면 누구나 읽을 수 있어서 "승인된 팀원만 접근"이 성립하지
않았습니다. 또한 로그인 화면을 우회해 콘솔에서 `google.script.run.getRestaurantData()`를
직접 호출할 수도 있었습니다.

- 계정 검증을 `code.gs`의 `verifyLogin()`으로 이동 (서버에만 존재)
- 성공 시 세션 토큰 발급(`CacheService`, 6시간). 모든 데이터 함수가 토큰을 요구하므로
  로그인 없이는 시트에 접근할 수 없습니다
- 세션 만료 시 로그인 화면으로 자동 복귀

### 정리만 한 것

- `innerHTML +=` 루프(50회 재파싱) → 배열 `join()` 한 번에 삽입
- `alert()` 검증 → 화면 내 메시지 영역으로 통일
- 인라인 `onclick` → `addEventListener`
- 뷰 전환 로직 3벌 → `showView()` 하나
- 버튼 CSS 3벌 중복 → `.btn` + 변형 클래스
- CSS `@import` → `<link>` (`@import`는 렌더링을 막습니다)
- `:hover` → `:hover:enabled` (처리 중인 버튼에도 hover 색이 먹었습니다)
- 열 인덱스 매직넘버 → 상수
- 아이디/비밀번호 칸에서 엔터로 로그인 가능
- `placeholder` 앞 공백 제거, `getElementById` 반복 → `$()` 헬퍼

## 남은 참고사항

- 잔액 시트에 `지역 + 식당명`이 중복된 행이 있으면 첫 번째 행만 갱신됩니다
- 세션 토큰은 메모리에만 두므로 페이지를 새로 고치면 다시 로그인해야 합니다
- `CacheService`는 부하에 따라 6시간 전에 만료될 수 있습니다. 이때는 "세션이
  만료되었습니다" 메시지와 함께 로그인 화면으로 돌아갑니다
